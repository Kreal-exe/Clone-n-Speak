# Clone'n'Speak 2.0 — подплан B: лёгкие аудио-функции (Task 6 мастер-плана)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Функции 1–12 раздела «Функции основного уровня» спецификации работают в основном (MLX, без PyTorch) окружении на любом Mac: экспорт, пакетная озвучка, пресеты, цепочка эффектов, сдвиг формант, DeepFilterNet3, «удалить музыку» (ONNX), расширенная проверка сэмпла, анализатор, LoRA по ссылке HF, плеер со скраббером и A/B, звук из видео. Новые страницы: **Аудио-инструменты** (`tools`) и лёгкая часть **Разделения** (`separator`).

**Architecture:** DSP — маленькие Python-модули `Sources/cns_*.py` рядом с `worker.py`. Общее (чтение/запись аудио, ошибки входа, реестр эффектов, автозагрузка модулей) — `cns_core.py`. `worker.py` трогает **только** задача 6.1: после неё модуль подключается сам (достаточно положить `Sources/cns_<имя>.py` с `COMMANDS = {...}`), общий файл `worker.py` больше не меняется. Нативное — Objective-C: экспорт форматов и декодирование (AVFoundation), виджеты на Core Graphics (волна, скраббер, спектрограмма), страницы. Данные анализатора считает воркер, рисует приложение.

**Tech Stack:** Python 3.11 рантайма (тесты — и на 3.9: без `X | Y` в рантайме, без `match`), numpy/scipy (уже в окружении), `onnxruntime==1.31.1` (ставится по кнопке, ~76 МБ), `deep-filter` 0.5.6 (скачивается по кнопке, ~27 МБ), AVFoundation/AppKit/Core Graphics.

**Spec / ссылки:** `docs/superpowers/specs/2026-11-09-clonenspeak-2.0-design.md` («Функции основного уровня», «Аудио-инструменты», «Разделение»); мастер-план Task 6; факты спайка (строки 11 и 12) — `.claude/worktrees/agent-a0377a62a8158d3d3/docs/superpowers/notes/2026-11-09-pro-engines-spike.md`, эталонная реализация MDX — `.claude/worktrees/agent-a0377a62a8158d3d3/tools/spikes/ort_vocals.py` (читать и переносить идею, не копировать вслепую); интерфейсы `OVJobs` — подплан D, task 8.1; помощники страниц (`OVPageHeader`, `OVPageScroll`, `OVFieldBlock`, `OVPopup`, `OVSwitch`, `OVTextArea`, `OVDisclosure`, `OVSegmented`) — подплан A, 5.0.

## Global Constraints

Всё из «Global Constraints» мастер-плана и подплана A (цвета только `OVColor`/`OVColorAlpha`, без эмодзи и теней, строки `L(@"…")`, размеры отступов, `accessibilityRole/Label/Value`, Reduce Motion) плюс:

- **Без тяжёлого в основном окружении.** Модули `cns_*.py` не импортируют `torch`, `mlx`, `matplotlib`, `librosa`, `soundfile` (только numpy/scipy/stdlib; `onnxruntime` — лениво, внутри функции). Тест `test_no_heavy_imports` (6.1). Пик памяти основного сценария (клон + 30 с речи, ~3 ГБ по README) не растёт: перед любым тяжёлым инструментом (`separate_*`, `dfn_*`) воркер выгружает модели (`core.free_models()`), 30-секундная обработка ONNX ≤ 2.5 ГБ.
- **stdout воркера — канал протокола.** Модули никогда не печатают в stdout; события — через `core.emit_status/emit_progress`; вывод внешних процессов (`deep-filter`) перехватывается.
- **Один источник истины для параметров эффектов** — `core.register_effect(...)` (имена, диапазоны, значения по умолчанию). UI строится по `fx_catalog`, пресеты проверяются по нему же; диапазоны в ObjC не дублируются.
- **Любой вход — работа или внятная ошибка.** Все файловые команды читают через `core.read_audio` и бросают `AudioInputError(code, message)`; `message` содержит действие («Cut it first: the limit is 20 minutes.»), без трейсбеков. Коды: `empty, too_short, silent, unsupported, too_long, bad_param`. Предел длины — `MAX_SECONDS = 1200` (20 мин) для всех инструментов; сжатые форматы (MP3/M4A/MP4) и видео декодирует приложение в WAV до вызова воркера (`OVDecodeAudio`).
- **Безопасность файлов.** Выходные пути команды пишутся атомарно (`.part` → `os.replace`), каталог вывода создаётся; бинарь и модели — скачивание по HTTPS с закреплённым SHA-256, при несовпадении файл удаляется и ошибка называет причину. Частично скачанное (`.part`) готовым не считается.
- **Параллельная работа.** Файлы задач не пересекаются (таблица ниже). Общие точки: `worker.py`, `build.sh`, `OVWorker.m` — только 6.1; `OVRuntime.m`, `OVPaths.*` — только 6.10; `OVPageRegistry.m` — по одной строке (`ph` → класс) в 6.16 и 6.17; `OVStore.*`, `OVSynthPage.m`, `OVSettingsPage.m` — только 6.19; `OVVoicesPage.m` — только 6.18; `OVModels.*`, `OVModelsPage.m` — только 6.20; `OVGalleryPage.m`, `tools/gen_xcodeproj.py`, `strings.py merge` — только 6.21.
- **Русские строки** — только в `Resources/ru.lproj/fragments/audio-<номер задачи>.strings`; общий `Localizable.strings` не трогать.
- **ObjC-тесты.** Foundation/AVFoundation-логика без страниц — `tests/objc/<имя>_test.m` + `tests/test_objc.py` (контракт подплана D 8.1: собирает каждый `tests/objc/*_test.m`, исходники берёт из строки `// deps: A.m B.m` в первой строке файла). Кто высаживается первым, тот создаёт `tests/test_objc.py` с этим контрактом; второй берёт чужую версию.
- Коммит на задачу, ветка `release/2.0`, английские сообщения + трейлер соавтора, как в остальных коммитах сессии. `python3 tools/gen_xcodeproj.py` в задачах не запускается (6.21).

## Task 6.2: Цепочка эффектов — `cns_fx.py`

# distortion{drive_db 0..40 =12; tone 0..1 =0.5; mix 0..1 =1}  · bitcrush{bits 1..16 =8; downsample 1..32 =1; mix 0..1 =1}

def apply_chain(wav, sr, chain, *, extend=True) -> np.ndarray
    # chain: [{"type": str, "on": bool = True, "params": {...}}]; параметры вне диапазона зажимаются; неизвестный type → ValueError("Unknown effect 'x'");
    # в конце — мягкий страховочный лимитер (колено 0.89, потолок 0.99) и nan_to_num; extend=True добавляет tail_seconds(chain)
def tail_seconds(chain, sr) -> float                         # хвост reverb (tail_s·room) и delay (до затухания −60 дБ, ≤ 4 с); 0 без них
COMMANDS: fx_catalog(req) -> {"effects": [{"id","title","params": {key: {min,max,default,unit,title}}}]}

POST_SYNTH hook: если в req есть непустой "chain": wav → apply_chain; если задан req["dry_out"], до обработки пишет сухой файл (для A/B)
