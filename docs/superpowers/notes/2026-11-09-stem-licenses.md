## Measurements

2026-11-18, Mac mini M4 16 GB, pro environment (audio-separator 0.45.0, torch 2.8.0), 30 s "speech + synthetic music"
(`tools/spikes/gen_audio.py`, mix SI-SDR of the speech: -4.0 dB), through `cns_stems.py separate` **under `sandbox-exec` with
`(deny network*)`** and the weights already installed. `peak` is the process's peak memory footprint (`time -l`).

| id | wall time (whole process / separation) | peak | SI-SDR of the speech |
|---|---|---|---|
| `kim-vocal-2` | 15.5 s / 12.0 s (6 s in the spike) | 7.2 GB (spike 6.5) | **21.1 dB** (target >= 20) |
| `bs-roformer` | 32.7 s / 30.3 s | 6.6 GB | **24.9 dB** (target >= 24) |
| `htdemucs` | 14.5 s | 2.3 GB | 11.4 dB on this synthetic bed (the fallback, not the quality tier) |
| `dereverb-anvuew` | 16.7 s | 6.3 GB | completes with dry and reverb stems (the test mix has no reverb, so no quality figure) |

Network: audio-separator, started with only the model file, fetches `download_checks.json`, `mdx_model_data.json` and
`vr_model_data.json` into the model folder (a hidden call to the UVR data host) and, for Demucs, wants the model by its
config name. Fix: those three lists are pinned snapshots (identical bytes) installed with every model, and Demucs is loaded as
`htdemucs.yaml`. With that, all four models separate with the network denied by the sandbox. Two more things a sandboxed
run needs: a writable numba cache (set by the script) and the per-user temp/cache folders in the write roots (onnxruntime's
CoreML provider writes there regardless of TMPDIR; `cns_stems.sandbox_write_roots` returns them).
